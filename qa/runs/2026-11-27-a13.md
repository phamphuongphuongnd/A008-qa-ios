## Lỗi mới (B-100…B-104)

- [ ] B-100 🔴 [TC-125, TC-127] Build release — APK release **có R8** (`android.enableMinifyInReleaseBuilds=true` mặc định của prebuild Expo SDK 58) **crash ngay khi mở**: `java.lang.RuntimeException: Unable to get provider androidx.startup.InitializationProvider … NoSuchMethodException: androidx.work.impl.WorkDatabase_Impl.<init> []` (WorkManagerInitializer). Nguyên nhân: `expo-background-task` kéo `work-runtime 2.10.5` → `room-runtime 2.6.1`, luật consumer của Room 2.6.1 là `-keep class * extends androidx.room.RoomDatabase` **không giữ `<init>()`**; R8 full mode (mặc định AGP 8+) xoá constructor (xem `android/app/build/outputs/mapping/release/configuration.txt` dòng ~1077; Room 2.7.0 đã sửa thành `{ void <init>(); }`). · Tái hiện: `gradlew app:assembleRelease -PreactNativeArchitectures=armeabi-v7a` → cài → mở · mong đợi mở bình thường vs crash · **bản store (.aab, cũng R8) sẽ crash 100 %**. Hướng sửa: thêm luật `-keep class * extends androidx.room.RoomDatabase { <init>(); }` qua config plugin (`expo-build-properties` `android.extraProguardRules` hoặc plugin riêng — `android/` là CNG, sửa tay sẽ mất) hoặc ép `androidx.room:room-runtime` ≥ 2.7; rồi thử lại bản R8 trên máy. Bản tắt R8 (`-Pandroid.enableMinifyInReleaseBuilds=false`) chạy bình thường.
- [ ] B-101 🔴 [TC-180, TC-182] S-22 — **deriveKey PBKDF2 310 000 vòng = 14 phút 7 giây trên A13 bản release** (máy ảo dev 14–16 phút → Hermes release không nhanh hơn). Tốc độ đo ~350 vòng/giây (10 000 vòng 28–31 s; 1 000 vòng ~3 s gồm cả phần khác). Lần đầu "Back up now" và **mọi lần Restore** (file 310k) đều phải chờ ~14 phút với "Preparing encryption…" / "Checking the backup…", luồng JS bận 100 %. Mục tiêu trong `format.ts:27` là ≤ ~3 s → bằng JS thuần chỉ được ~1 000 vòng (thấp xa mức OWASP 600 000). Hướng: PBKDF2 **native** (vd. `react-native-quick-crypto` hoặc module Kotlin/Swift nhỏ gọi `SecretKeyFactory PBKDF2WithHmacSHA256` / CommonCrypto) rồi đo lại và chốt `BACKUP_KDF`; file cũ vẫn đọc được vì số vòng ghi trong header. (Cần Phương duyệt thêm thư viện native.)
- [ ] B-102 🟡 [TC-181] S-22 — Chọn thư mục **Google Drive** → dòng hiện "Folder: acc=6;doc=encoded=ZEWjKw-Yc2Tl…" (id tài liệu SAF thô, dài) thay vì tên thư mục "EvenleaseQA"; thư mục cục bộ thì hiện đúng "Folder: EvenleaseQA". Drive là trường hợp chính (gợi ý "Into a Google Drive folder") · cùng họ B-76(c) — nên lấy `DocumentFile.getName()` / `queryDocument` tên hiển thị · ảnh `a13-tc181-drive`.
- [ ] B-103 🟡 [TC-178] S-23 / Settings — A13 có cả nhận diện khuôn mặt và vân tay: app ghi "Require **Face unlock** to open" nhưng hộp hệ thống chỉ hỏi **vân tay**. `lockNative.ts:31` chọn 'face' khi `supportedAuthenticationTypesAsync()` có FACIAL_RECOGNITION (phần cứng hỗ trợ, không phải đã đăng ký / đủ mạnh — Samsung face là Class 2, BiometricPrompt dùng vân tay) · mong đợi "Require fingerprint to open" (hoặc chữ trung tính "Require fingerprint or face…").
- [ ] B-104 🟡 [TC-195] Quyền release — `FOREGROUND_SERVICE` (app không có dịch vụ tiền cảnh) và `WRITE_EXTERNAL_STORAGE maxSdkVersion=28` vẫn nằm trong APK release → thêm vào danh sách gỡ của `plugins/withReleasePermissions.js` (hoặc ghi lý do) trước khi điền Data safety. ACCESS_LOCAL_NETWORK / CHANGE_WIFI_MULTICAST_STATE đã không còn ở release (chỉ dev client) → đóng phần đó của TODO(6B).
